# Probe 001-A — trigger contract

Status: THROWAWAY / STATIC REPRESENTABILITY PROBE

Question: can the desired automatic-memory behavior be expressed using the documented ChatGPT Plugin = Skills + Apps package model, without assuming an undocumented lifecycle hook?

This probe intentionally uses an unresolved placeholder app id. It proves the package/skill contract shape, not that ButlerBrain or Basic Memory currently exposes a public plugin dependency id suitable for redistribution.

Acceptance criteria:

1. Plugin manifest uses only documented `skills` and `apps` fields for the integration mechanism.
2. Skill frontmatter is broad enough to be eligible for automatic selection on continuity-sensitive non-trivial turns.
3. Recall is ordered before substantive work.
4. Recalled memory is explicitly non-authoritative evidence.
5. Search miss is not promoted to absence.
6. Retention is a compact durable delta, not transcript dumping.
7. Retention occurs before final response because no public post-turn callback is assumed.
8. Skill explicitly states that model-mediated triggering is not guaranteed every-turn lifecycle.
9. Portable provider binding remains unresolved until the provider's canonical App id/package is known.
